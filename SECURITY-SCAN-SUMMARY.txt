[CRITICAL-001] Timing Attack in Token Comparison
  File:        backend/app/middleware/security.py
  Line:        53
  CWE:         CWE-208 (Observable Timing Discrepancy)

  Vulnerability:
    Python's == operator on bytes is NOT constant-time. Returns False
    immediately on first byte mismatch, leaking token information through
    response-time side-channel. Attackers can forge CSRF tokens by timing
    response delays (256×32 = 8,192 measurements sufficient).

  Current Code:
    return hashlib.sha256(provided.encode()).digest() == hashlib.sha256(stored.encode()).digest()

  Fixed Code:
    import hmac
    return hmac.compare_digest(provided, stored)

  Impact:
    - Authentication bypass via token forgery
    - Timing leaks expose token structure
    - Session hijacking vulnerability

  Fix Time:  2 minutes
  Severity:  CRITICAL - Authentication threat

[HIGH-001] Fresh Requests Cannot Obtain CSRF Tokens
  File:        backend/app/middleware/security.py
  Line:        76-79
  CWE:         CWE-352 (CSRF)

  Issue:
    Client making first POST/PUT/DELETE has no CSRF token yet.
    Middleware returns 403 with token in response, but client
    cannot use it for the rejected request. Catch-22 situation.

  Impact:
    - Breaks form submission on fresh page loads
    - Requires JavaScript workaround (OPTIONS preflight)
    - Poor UX: extra round-trip needed
    - Mobile apps may fail CORS preflight

  Fix:  Add /api/csrf-token endpoint or return 200 for fresh requests
  Time: 10 minutes

[HIGH-002] Insecure Frontend Cookie Parsing
  File:        frontend/src/login.js
  Lines:       295-298, 322-330
  CWE:         CWE-200 (Information Exposure)

  Issues:
    1. Manual cookie parsing with document.cookie.split()
       - Fragile, prone to whitespace/encoding errors
       - No URL decoding of cookie values
       - Fails silently with undefined→empty string

    2. Race condition in token fetch
       - await fetch(OPTIONS) may complete before browser
         updates document.cookie
       - getCSRFToken() called too early, gets empty string
       - Timing-dependent, works sometimes, fails others

  Current:
    let csrfToken = getCSRFToken();
    if (!csrfToken) {
      await fetch('/api/auth/login', { method: 'OPTIONS' });
      csrfToken = getCSRFToken();  // Race condition!
    }

  Fix:  Use response header instead of cookie parsing
        Use async getCSRFToken() that fetches if needed

  Time: 5 minutes

[MEDIUM-001] Form Field Token Validation Broken
  File:      backend/app/middleware/security.py
  Lines:     85-100
  CWE:       CWE-400 (Uncontrolled Resource Consumption)

  Problem:   Request body can only be read once. Middleware attempts
             to read body for form field extraction after headers
             checked, but body may already be consumed.

  Impact:    Form field token validation silently fails
             Clients forced to use header only

  Fix:       Use request.form() instead of raw body parsing

[MEDIUM-002] Token Rotation on Every Request
  File:      backend/app/middleware/security.py
  Lines:     113-127

  Problem:   New token generated per response, not per session.
             Breaks client caching: token A accepted in request,
             invalidated in response, causing 403 on next request.

  Impact:    AJAX workflows fail after multiple requests
             Token mismatch between client cache and server cookie

[MEDIUM-003] No Server-Side Token Expiration
  File:      backend/app/middleware/security.py
  Lines:     119-124

  Problem:   Cookie max_age=3600 but no server-side timestamp check.
             No validation that token was issued < 1 hour ago.

  Impact:    Old stolen tokens remain valid indefinitely
             No token revocation on logout

[MEDIUM-004] Race Condition in Token Fetch
  File:      frontend/src/login.js
  Lines:     322-330

  Problem:   OPTIONS preflight request async; cookie update async.
             No guarantee cookie available before getCSRFToken() called.

  Impact:    Token fetch fails intermittently (timing-dependent)
             User login fails on slow connections

[MEDIUM-005] No Session-Based Token Revocation
  File:      backend/app/middleware/security.py

  Problem:   Tokens not linked to session/user_id.
             Cannot revoke all tokens on logout.
             Stolen tokens remain valid after user logs out.

  Impact:    Stolen token attack window extends indefinitely
             No per-user token invalidation on password change
